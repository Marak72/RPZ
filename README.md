# РПЗ — веб-приложение для блокировки доменов ФСТЭК

Внутреннее веб-приложение для учёта и наглядного отображения вредоносных доменов и
IP-адресов из писем ФСТЭК, блокируемых на DNS-сервере BIND через RPZ-зону.

## Возможности

- 📊 **Дашборд** для руководства: сколько доменов заблокировано, когда и кем
  обновлялся список.
- 🛡️ **Просмотр заблокированного** — данные читаются **напрямую из живого файла
  RPZ-зоны** (`/var/named/master/rpz.block.db`) на DNS-сервере по SSH.
- 🔄 **Обновление по кнопке**: приложение подключается по SSH под заданной учётной
  записью, читает файл, отключается и сохраняет снимок (с историей).
- 📄 **Парсер писем ФСТЭК**: загрузка `.docx`/`.odt`/`.pdf`, точное извлечение индикаторов
  (в т.ч. замаскированных `example[.]com`, `hxxp[:]//`), без мусора из имён вложений,
  названий ПО и ссылок-источников; предпросмотр по категориям и сохранение.
- 📬 **Архив писем**: сам файл письма хранится целиком, PDF открывается прямо в браузере;
  у каждого индикатора видно, из какого письма он пришёл, и наоборот.
- 🔎 **Карточка индикатора**: вся информация об объекте на одной странице — статус,
  наличие в зоне, письмо-источник, вердикт VirusTotal, заметки, история выгрузок
  и действия (заблокировать / снять блокировку / удалить).
- 🧪 **VirusTotal**: проверка домена или IP по кнопке и пакетно, вердикт и баллы
  сохраняются в базе и показываются в таблицах.
- ✍️ **Ручное добавление** доменов и IP — для индикаторов не из писем.
- 🧯 **Защищённые домены**: список, который приложение никогда не выгрузит в блокировку.
- 🗂 **Разбивка по категориям**: домены, IP-адреса, URL с путями, хеши — отдельными
  разделами и вкладками.
- 🔗 **URL с путями** — отдельный раздел: RPZ не умеет блокировать пути, такие
  индикаторы блокируются на прокси/WAF (хост при этом попадает в домены).
- 🔑 **Хеши IoC**: sha256/sha1/md5 сохраняются отдельным списком (для SIEM).
- ⬆️ **Выгрузка в RPZ** с выбором доменов: видно, какие уже в зоне, а какие нет;
  предпросмотр без изменений, резервная копия, проверка `named-checkzone`,
  `rndc reload` и автоматический откат при ошибке. Журнал всех выгрузок.
- ⬇️ **Снятие блокировки**: удаление доменов из зоны по той же безопасной процедуре.
- 📊 **Экспорт CSV** в каждом разделе и прямо из предпросмотра письма.
- 🔐 **Авторизация** с ролями: `operator` (полный доступ) и `manager` (только просмотр).
- 🔑 Учётная запись SSH задаётся в веб-интерфейсе, пароль хранится **зашифрованным**
  (Fernet).

## Выгрузка в боевую RPZ-зону

DNS-сервер боевой, поэтому выгрузка построена так, чтобы её нельзя было сломать.
Порядок шагов (`app/services/rpz_writer.py`):

1. Читается текущая зона; домены, уже присутствующие в ней, пропускаются.
2. Каждый домен проходит строгую валидацию — в зону не может попасть мусор
   (имена файлов, IP, пути). IP-адреса в RPZ **не выгружаются** — их блокируют
   на межсетевом экране.
3. Serial в SOA увеличивается автоматически (формат `YYYYMMDDNN`, всегда растёт).
4. Новое содержимое кладётся во **временный** файл — боевой ещё не тронут.
5. `named-checkzone` проверяет синтаксис. Не прошло — процедура останавливается,
   боевой файл остаётся прежним.
6. Создаётся резервная копия `zone.db.bak-<метка времени>` рядом с зоной.
7. Установка через `cat tmp > zone` — файл сохраняет владельца, права и контекст
   SELinux (в отличие от `mv`).
8. `rndc reload <зона>`, затем контрольное перечитывание зоны.
9. **Любая ошибка после шага 7 → автоматический откат** из резервной копии и reload.

Начинать всегда стоит с кнопки **«Предпросмотр»** — она выполняет шаги 1–5 и
показывает точный дифф, ничего не меняя на сервере.

### Настройка учётной записи на DNS-сервере (минимальные привилегии)

Рекомендуемый вариант: права на файл зоны выдаются через группу, а под `sudo`
разрешается ровно одна команда — перезагрузка зоны.

```bash
# 1. Отдельная учётная запись (shell нужен: команды выполняются по SSH)
useradd -r -m -s /bin/bash rpzbot && passwd rpzbot

# 2. Права на зону через группу BIND (уточните её: ps -o user,group -C named)
usermod -aG named rpzbot
chown root:named /var/named/master/rpz.block.db
chmod 664 /var/named/master/rpz.block.db   # запись в файл зоны
chmod 770 /var/named/master                # создание резервных копий рядом

# 3. Только одна команда через sudo (visudo)
#    rpzbot ALL=(root) NOPASSWD: /usr/sbin/rndc reload rpz.block
```

В настройках приложения включить **«Только rndc reload через sudo -n»**;
галочку «файловые операции через sudo» оставить выключенной.

Что каким правом обеспечивается:

| Шаг выгрузки | Требуется |
|---|---|
| чтение зоны, `cat tmp > zone.db` | запись на **файл** (владелец, права и контекст SELinux сохраняются) |
| `cp -p zone.db zone.db.bak-<метка>` | запись на **каталог** зоны |
| `named-checkzone` | ничего: обычный бинарь, читает файл в `/tmp` |
| `rndc reload <зона>` | правило sudoers выше (вызывается напрямую, без `sh -c`) |

Галочка «файловые операции через sudo» нужна, только если права через группу
выдать нельзя — она требует широкого правила sudo (`sh -c`) и потому менее
безопасна.

Кнопка «Проверить подключение» проверяет всё перечисленное (включая право на
запись и разрешение в sudoers через `sudo -l`, ничего не выполняя) и показывает
отчёт.

## Стек

Python · Flask · SQLAlchemy (SQLite) · Flask-Login · Bootstrap 5 · paramiko · cryptography

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Необязательно — распознавание индикаторов **из PDF** (см. `requirements-optional.txt`):

```bash
pip install -r requirements-optional.txt
# если PyPI закрыт, но доступен GitHub:
pip install "pypdf @ git+https://github.com/py-pdf/pypdf@4.3.1"
```

Без `pypdf` приложение работает полностью: письма в PDF сохраняются, открываются
в браузере и привязываются к индикаторам — не работает только автоматическое
извлечение индикаторов из PDF (их можно добавить вручную).

### Переменные окружения

```bash
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
export RPZ_FERNET_KEY="$(python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())')"
```

`RPZ_FERNET_KEY` обязателен — без него нельзя сохранять/читать пароли SSH.
Сохраните его в надёжном месте: при смене ключа сохранённые пароли расшифровать нельзя.

### Инициализация базы данных

С использованием миграций:

```bash
export FLASK_APP=run.py
flask db upgrade
```

Или быстрый старт без миграций:

```bash
flask init-db
```

### Создание пользователя

```bash
flask create-user admin --role operator
flask create-user boss  --role manager
```

Сменить пароль существующего пользователя (например, если забыли):

```bash
flask set-password admin
```

### Запуск

```bash
python run.py
# открыть http://localhost:5000
```

## Использование

1. Войдите под учётной записью оператора.
2. В разделе **Настройки** укажите УЗ для SSH (хост, логин, пароль, путь к файлу зоны)
   и нажмите «Проверить подключение».
3. На странице **Заблокировано** нажмите «Обновить с сервера (SSH)» — файл RPZ будет
   считан и показан в виде таблицы. Каждое чтение сохраняется в **истории**.
4. Загружайте письма ФСТЭК в разделе **Загрузить письмо** — индикаторы будут
   извлечены, показаны для проверки и сохранены как кандидаты.
